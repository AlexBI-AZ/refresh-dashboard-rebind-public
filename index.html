How Rebind works

Rebind replaces workspace, dataflow and dataset GUIDs in every .tmdl and .json file of a local PBIP report folder.

  1. Enter the old and new GUID pairs.
  2. Click Scan to see what would change. Nothing is written.
  3. Review the summary, then choose whether to Apply.

Apply edits the files in place. Make sure the project is under version control first.

            Справка

            Что это такое

            Панель управления для двух независимых операций с Power BI / Fabric:

            • Refresh - обновление нескольких Dataflow, затем нескольких семантических моделей через Power BI REST API. Модели запускаются только после успешного завершения всех dataflow. Флажок Model only обновляет только модели, без dataflow; он действует на один запуск и не сохраняется в профиле. Рабочие области, отчеты, модели и dataflow выбираются поиском по названию; при выборе отчета или модели ее dataflow добавляются сами (по lineage). GUID можно вставить в свернутом разделе IDs and manual entry.
            • Rebind - замена GUID рабочих областей и dataflow в исходном коде PBIP-проекта. Сканирует .tmdl файлы семантической модели, находит старые GUID, заменяет на новые, и проверяет результат.

            Вкладка Refresh

            Как работает цепочка Refresh:

            • Запуск всех dataflow одновременно
            • Ожидание завершения всех (проверка каждые 30 секунд)
            • После успешного завершения всех dataflow - параллельный запуск всех семантических моделей
            • Каждая модель показывает собственный статус; ошибка одной не отменяет остальные
            • Если заполнено Notify colleagues, после цепочки отправляется одно итоговое письмо через Power Automate
            • Прогресс отображается точками: синяя = в процессе, зеленая = готово, красная = ошибка

            Что нужно: доступ к рабочей области Power BI / Fabric (роль Member или выше), установленный модуль MSAL.PS.

            Тайминги: статус dataflow и каждой семантической модели проверяется каждые 30 секунд. Максимальное общее время ожидания - 11 часов. Если за это время обновление не завершилось - таймаут и ошибка. Сами операции выполняются на стороне Fabric, так что время зависит от объема данных и загрузки capacity.

            Вкладка Rebind

            Двухшаговый процесс:

            • Scan (только чтение) - находит все вхождения старых GUID в .tmdl и .json файлах. Показывает контекст для каждого совпадения. Не изменяет проект.
            • Apply (замена + проверка) - заменяет старые GUID на новые во всех затронутых файлах, затем проверяет, что старых GUID не осталось.

            Важно: после Scan просмотрите отдельное понятное резюме под техническим логом и выберите, продолжить Apply или остановиться. Изменения применяются на месте - убедитесь, что проект под версионным контролем.

            Аутентификация

            Сервер и окно панели запускаются без входа. Для Refresh есть два равноправных способа входа; способ выбирается на каждом компьютере в setup.bat:

            • Device code - для тех, кто запускает обновления вручную. Вход под своей учетной записью (свои права, свое имя в журнале обновлений). Нажмите «Authenticate for Refresh», откройте https://login.microsoft.com/device и введите код из консоли; вход сохраняется в зашифрованном кэше
            • Сертификат (service principal) - для компьютеров, где обновления идут без участия человека. setup.bat создает сертификат с неэкспортируемым ключом на этом компьютере и задает переменные POWERBI_REFRESH_AUTH_MODE, POWERBI_REFRESH_TENANT_ID, POWERBI_REFRESH_CLIENT_ID, POWERBI_REFRESH_CERT_THUMBPRINT; владелец приложения загружает его открытую часть (.cer). Вход не нужен

            Если заданы переменные сертификата, используется сертификат, иначе device code; POWERBI_REFRESH_AUTH_MODE задает способ явно. setup.bat -CheckOnly проверяет готовность, ничего не меняя.

            Вкладка Rebind не требует аутентификации или MSAL.PS - она работает только с локальными файлами.

            Где что лежит

            • setup.bat - установка для текущего пользователя и проверка готовности
            • launch-app.bat - запуск панели в отдельном окне (на него указывают ярлыки)
            • launch.bat - запуск сервера в видимой консоли
            • server.ps1 - HTTP-сервер и API-логика
            • index.html - веб-интерфейс
            • profiles.json - сохраненные профили Refresh
            • rebind-profiles.json - сохраненные профили Rebind
            • runtime\ - общий движок обновления (тот же, что у Claude-скилла)
            • validation\ - проверки до и после обновления и письмо о результате
            • logs/ - папка с логами ошибок

            Типичные проблемы

            • Браузер открывается, но страница не грузится - подождите 5 секунд, обновите страницу
            • «Not Authenticated» после входа - закройте окно панели и запустите ярлык заново; setup.bat -CheckOnly покажет причину
            • «Not Authenticated» на вкладке Rebind - нормально, Rebind не требует аутентификации
            • Ошибка «Dataflow refresh FAILED» - проверьте роль в рабочей области (нужен Member или выше)
            • Rebind: кнопка Apply неактивна - сначала выполните Scan и дождитесь «SCAN COMPLETE» в логах
            • Refresh: статус «Starting...» и ничего не происходит - проверьте logs\worker-start.log
            • Порт 8765 занят - закройте другие экземпляры сервера
